# Agent rules

A new change copies the nearest example. Resource rules live only in the `State` methods of `internal/domain`. Storage writes go through the single path `repository.commit`. A gRPC handler moves values and calls exactly one `network.Service` method.

## English only

Write everything in this repo in English: README, code comments, docs, AGENTS.md, QUALITY.md, PR and issue templates, commit messages, PR and issue bodies, review comments and `Verified-by` sections. The `english` job in CI runs `scripts/check-english.sh`: `files` fails on a tracked file with Hangul unless `.github/english-allowlist` lists it as `<glob> <reason>` (only test data and user-facing UI strings belong there), and `text` and `commits` reject Hangul in the PR body and the PR's commit messages with no exception.

## Branches and atomic commits

Do not commit or push to `main` directly. Create a work branch and push only from it. Cloud work branches in this repository are named `cursor/<description>-<number>`.

A commit holds one change. Split into units that can be read and reverted separately, such as domain rules, storage and service, and gRPC. Do not mix format-only commits with behaviour changes.

## pstack

For a design that crosses a call boundary, use architect before writing code. Make two sketches of different shapes and pick the one where each invariant has a single owner.

Before merging an implementation, use interrogate. Different models look at the same diff, and only the valid findings are fixed.

When the same kind of mistake repeats, use correct. Fix in this order: structure, types, a lint that shows the cause of failure, tests, docs. When a rule is added to this table, its enforcer cell must not be empty. A rule that is only a sentence with no check that can break does not exist yet.

All coding and development work follows the pstack poteto-mode style: keep answers short and simple, make the smallest code change, and report only what was actually run.

## Insider-risk guardrails

Bots are insider risks too. The rules below have no exceptions.

1. **Independent verification**: an important result (merge, security, data) is never verified by the bot/model that wrote it. Another bot (or a person) verifies it. (Process rule; CI cannot enforce it.)
2. **Records**: every change leaves a trail of issue → PR (`Part of #N`) → commits. Work logs go in the PR body or issue comments in a form people can read. No force-push or history rewriting (except with the user's approval).
3. **Failure tests**: a new feature is not tested on the happy path only. Include at least one case each for power loss/restart, idempotent re-run and malicious or boundary input, or state in the PR why that is not possible.
4. **Least privilege**: no direct pushes to main. Every change is a single PR from its own branch cut from main. No stacked PRs. No local merges. Tokens are scoped to the repo. RBAC covers only the resources the service code actually calls, as a Role (namespace scope) where possible.
5. **Separated audit**: author bot ≠ verifier bot ≠ merge decision. An author bot never merges its own PR. Merge only when base==main and every CI check on the head commit is success.
6. **Isolation and emergency stop**: a bot/agent is stopped immediately at the user's request or by the orchestrator stopping that bot's session and revoking its token (`gh auth`/PAT revoke). Risky work happens only in a sandbox (the box or a throwaway cluster). No access to production clusters.
7. **Incident disclosure**: rule violations and incidents are never hidden; record them in an issue as `Cause / Impact / Action / Prevention` (label `incident`).

This repo has no server-side protection (private, free plan). 1, 5 and 6 are process rules. For parts of 2 and 4, `.github/workflows/repo-guard.yml` checks the PR's base, `Part of #N` and that no PR text or commit closes an issue, and `.github/workflows/direct-push-watch.yml` reports after the fact any commit that reached main without a PR. This is detection, not blocking. The guard code is `scripts/guard-agents.sh`, and `make guard` runs `selftest` and `agents`.

Additional rules for this repo:

- A change that alters network isolation, such as security groups, SNAT, elastic IPs or subnet deletion, is merged only after a bot other than the author bot, or a person, has verified it.
- Real Kube-OVN verification belongs to the T2 lab; items that could not be verified go in the "Not verified" section of the PR body.
- Never write AWS account ID numbers in issues, PR bodies or code.
